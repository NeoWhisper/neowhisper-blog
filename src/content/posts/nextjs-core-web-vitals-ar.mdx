## المقدمة

تعد مؤشرات الويب الحيوية الأساسية مقاييس بالغة الأهمية تستخدمها جوجل لتقييم تجربة المستخدم وترتيب نتائج البحث. مع استمرار تطور نكست جي إس (Next.js) مع موجه التطبيقات (App Router) ومكونات الخادم (Server Components)، يتطلب تحسين هذه المقاييس فهمًا عميقًا لكيفية قيام إطار العمل بعرض الصفحات وتقديم الأصول إلى المتصفح.

يبحث هذا المقال في كيفية تحسين مؤشرات الويب الحيوية الثلاثة الأساسية—أكبر عملية رسم محتوى (LCP)، والاستجابة للتفاعل التالي (INP)، وانزياح التخطيط التراكمي (CLS)—على وجه التحديد داخل بيئة نكست جي إس.

## تحسين أكبر عملية رسم محتوى (LCP)

يقيس مقياس (LCP) أداء التحميل. لتوفير تجربة مستخدم جيدة، يجب أن يحدث (LCP) خلال أول 2.5 ثانية من بدء تحميل الصفحة. في تطبيقات نكست جي إس، يكون عنصر (LCP) عادةً هو صورة البطل الرئيسية أو كتلة نصية كبيرة.

### دور `next/image`

يعمل مكون `Image` في نكست جي إس على تبسيط عملية تحسين الصور. ومع ذلك، يمكن أن يؤدي التكوين الخاطئ له إلى الإضرار بمقياس (LCP).

**أفضل الممارسات الرئيسية:**

- **استخدام خاصية `priority`:** أضف دائمًا خاصية `priority` إلى صورة (LCP) الخاصة بك (مثل لافتة البطل). هذا يخبر نكست جي إس بالتحميل المسبق للصورة، مما يمنع تحميلها ببطء (Lazy Loading).
- **تحديد `sizes` صريحة:** عند استخدام الصور سريعة الاستجابة مع خاصية `fill`، قم بتوفير سمة `sizes`. هذا يسمح للمتصفح بتنزيل الصورة ذات الحجم الصحيح للشاشة، مما يقلل من النطاق الترددي ويسرع عملية العرض.

```tsx
import Image from 'next/image'

export default function Hero() {
  return (
    <div className="relative w-full h-[500px]">
      <Image
        src="/hero-banner.jpg"
        alt="Hero Banner"
        fill
        priority
        sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
        className="object-cover"
      />
    </div>
  )
}
```

## تحسين الاستجابة للتفاعل التالي (INP)

يقيس مقياس (INP) الاستجابة. ويقوم بتقييم الاستجابة الكلية للصفحة لتفاعلات المستخدم من خلال ملاحظة زمن الانتقال لجميع تفاعلات النقر واللمس ولوحة المفاتيح التي تحدث طوال فترة زيارة المستخدم.

### تقليل حظر المسار الرئيسي

تعمل مكونات خادم تفاعل نكست جي إس (React Server Components) على تقليل كمية جافا سكريبت (JavaScript) المرسلة إلى العميل بشكل كبير. من خلال الاحتفاظ بالتبعيات الثقيلة على الخادم، يمكنك تحرير المسار الرئيسي، مما يؤدي إلى تحسين (INP) بشكل مباشر.

**خطوات قابلة للتنفيذ:**

- **نقل المنطق إلى الخادم:** قم بجلب البيانات وعرض واجهة المستخدم الثابتة على الخادم. استخدم فقط مكونات العميل (`"use client"`) للعناصر التفاعلية.
- **تأجيل البرامج النصية غير الحرجة:** استخدم `next/script` مع استراتيجية `strategy="lazyOnload"` للبرامج النصية التابعة لجهات خارجية (مثل التحليلات أو أدوات الدردشة) التي لا تحتاج إلى التنفيذ فورًا.

## منع انزياح التخطيط التراكمي (CLS)

يقيس مقياس (CLS) الاستقرار البصري. يضمن انخفاض (CLS) عدم انزياح الصفحة بشكل غير متوقع أثناء تحميل المحتوى، مما يمنع المستخدمين من فقدان مكانهم أو النقر عن طريق الخطأ على الزر الخطأ.

### التخطيطات المستقرة مع نكست جي إس

غالبًا ما تحدث انزياحات التخطيط عند تحميل الصور أو الإعلانات أو الخطوط الديناميكية بشكل غير متزامن دون مساحة محجوزة.

**تقنيات المنع:**

- **حجز مساحة للمحتوى الديناميكي:** إذا كنت تقوم بجلب البيانات من جانب العميل، فقم دائمًا بعرض هيكل تحميل أو عنصر نائب بالأبعاد الدقيقة للمحتوى المتوقع.
- **أبعاد الصورة الصريحة:** عند عدم استخدام خاصية `fill`، قم دائمًا بتوفير خصائص `width` و `height` صريحة لمكون `next/image`. يسمح هذا للمتصفح بحجز نسبة العرض إلى الارتفاع الصحيحة قبل تنزيل الصورة.

## ماذا يعني هذا لبيئة الإنتاج

ينتج عن تنفيذ تحسينات الأداء هذه فوائد ملموسة:

- **تجربة مستخدم أفضل:** تؤدي أوقات التحميل الأسرع والتفاعلات السلسة إلى تقليل معدلات الارتداد.
- **تصنيفات بحث أعلى:** تعطي محركات البحث الأولوية للصفحات السريعة والمستقرة.
- **تكاليف نطاق ترددي أقل:** تؤدي الصور المحسّنة وتقليل جافا سكريبت من جانب العميل إلى خفض تكاليف خروج بيانات الخادم.


## مراقبة مؤشرات أداء الويب الأساسية في بيئة الإنتاج

التحسين ليس مهمة لمرة واحدة؛ بل يتطلب مراقبة مستمرة. في بيئات الإنتاج الحقيقية، لا تكفي البيانات المخبرية (من Lighthouse). أنت بحاجة إلى بيانات ميدانية — مقاييس يتم جمعها من المستخدمين الفعليين الذين يختبرون تطبيقك في ظروف شبكة وقدرات أجهزة مختلفة.

### الاستفادة من Vercel Analytics و Speed Insights

إذا كنت تستضيف تطبيق Next.js الخاص بك على منصة Vercel، فإن تفعيل **Vercel Speed Insights** يوفر طريقة لا تحتاج إلى إعدادات مسبقة لتتبع مؤشرات أداء الويب الأساسية الخاصة بك. تقوم هذه الأداة بحقن نص برمجي صغير في تطبيقك يرسل تقارير LCP و INP و CLS إلى لوحة التحكم الخاصة بك في الوقت الفعلي.
- **بيانات دقيقة:** يمكنك تقسيم بيانات الأداء حسب الصفحة والبلد ونوع الجهاز.
- **ملاحظات في الوقت الفعلي:** يمكنك رؤية تأثير النشر على مقاييس الأداء فوراً.

لدمجها يدوياً في إعداد خادم Next.js مخصص، يمكنك استخدام حزمة \`@vercel/speed-insights\`.

### Google Search Console وتقرير تجربة مستخدم Chrome (CrUX)

لأغراض تحسين محركات البحث (SEO)، المصدر النهائي للحقيقة هو تقرير تجربة مستخدم Chrome (CrUX). هذه البيانات هي ما يستخدمه بحث Google لترتيب النتائج.
يجب عليك مراقبة **تقرير مؤشرات أداء الويب الأساسية في Google Search Console** بانتظام.
- يقوم بتجميع البيانات عبر نافذة زمنية مدتها 28 يوماً.
- يسلط الضوء على مجموعات روابط محددة تفشل في الوصول إلى حد "جيد".

من خلال مقارنة بيانات Vercel Analytics في الوقت الفعلي مع بيانات CrUX ذات الـ 28 يوماً، يمكنك تحديد التراجعات بسرعة قبل أن تؤثر على تصنيفات البحث الخاصة بك.

### تنفيذ تتبع مخصص لمؤشرات الويب الأساسية

إذا كنت تستخدم واجهة خلفية مخصصة أو مزود تحليلات مختلف (مثل Datadog أو Sentry أو Google Analytics 4)، فإن Next.js يوفر خطافاً (Hook) مدمجاً يسمى \`useReportWebVitals\`.

\`\`\`tsx
'use client'

import { useReportWebVitals } from 'next/web-vitals'

export function WebVitals() {
  useReportWebVitals((metric) => {
    // إرسال إلى مزود التحليلات الخاص بك
    const body = JSON.stringify(metric)
    const url = 'https://example.com/analytics'
    
    // استخدام \`navigator.sendBeacon()\` إذا كان متاحاً، أو التراجع إلى \`fetch()\`
    if (navigator.sendBeacon) {
      navigator.sendBeacon(url, body)
    } else {
      fetch(url, { body, method: 'POST', keepalive: true })
    }
  })
}
\`\`\`

ضع هذا المكون في التخطيط الأساسي (Root Layout) الخاص بك لالتقاط المقاييس عبر تطبيقك بالكامل. يضمن هذا التتبع الدقيق تلبية ميزانيات الأداء وبقاء رحلات المستخدم المحددة سريعة ومتجاوبة.

## الخاتمة

يتطلب تحسين مؤشرات الويب الحيوية الأساسية في نكست جي إس نهجًا مدروسًا للعرض وتقديم الأصول والتفاعل. من خلال الاستفادة من مكونات الخادم، وتكوين `next/image` بشكل صحيح، وحجز مساحة للمحتوى غير المتزامن، يمكن للمطورين بناء تطبيقات تقدم تجارب مستخدم ممتازة وتحتل مراتب عالية في محركات البحث.
